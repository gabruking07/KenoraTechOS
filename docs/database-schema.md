# Database schema

Mongoose collections include User, Project, Folder, Task, Milestone, ActivityLog, Category, Technology, WorkspaceRecord, StoredDocument, and Backup. All operational models include created/updated timestamps. Projects have a unique slug, text search, and status/update indexes. Folders refer to a parent folder and may be resource folders; project links are optional. Tasks reference projects and milestones. Milestones reference projects and dependent milestones. Workspace modules (including clients, invoices, security findings, deployments, and notifications) are typed record groups in `WorkspaceRecord.fields`, not separate collections. Sessions are held in MongoDB by connect-mongo and are excluded from full backups.

Stored document metadata and embedded version metadata live in `StoredDocument`; file bytes live behind the document storage adapter. New backup history metadata lives in `Backup`; compressed backup bytes are stored through the same adapter, not in a MongoDB snapshot document. Older metadata-only backups may still have an inline `snapshot` field. No schema change drops collections or records. Additional supporting indexes are declared in model schemas; use additive `createIndex` operations after checking existing data, and avoid `syncIndexes` on production databases.

Phase 3 adds separate `BusinessClient`, `BusinessLead`, `BusinessService`, `BusinessProposal`, `BusinessInvoice`, `BusinessPayment`, `BusinessTransaction`, `BusinessTestCase`, `BusinessTestExecution`, `BusinessTechnicalDebt`, `BusinessInfrastructure`, `BusinessDeployment`, and `BusinessNotification` collections. Monetary values use integer minor units (INR amounts are paise), with an ISO currency code stored on each document. Legacy `WorkspaceRecord` rows remain present and continue to use the existing API; the opt-in business migration records the source row ID and never deletes the source. Full backups include the new collections. Do not run `syncIndexes`; inspect existing data and deploy new indexes additively.

Phase 4 adds `AutomationWorkflow`, `AutomationExecution`, and `AutomationWorkerStatus`. Workflow state includes trigger/action configuration, next scheduled time, lease fields, and run keys; execution records are idempotently keyed. `Task.automationKey` and `BusinessNotification.dedupeKey` are sparse unique idempotency keys. Business notifications also store category, priority, archive time, and delivery status; the currently supported delivery is in-app only. Full archive backups include workflows and execution history. Restored workflows are disabled, and snapshots marked running are restored as failed for explicit review. The worker heartbeat is operational state and is not a guarantee of provider or database availability.
