# User guide

Sign in with the admin account seeded from environment variables. Dashboard metrics are computed from saved MongoDB records. Add projects from All Projects; project status, budget and other unknown values are not assumed. Use search and status filters to find records. Archiving preserves a project; the API also supports restore. AI integration screens still show provider configuration and do not claim business workflows are connected to an AI provider.

Phase 3 business pages use dedicated MongoDB collections. Client and lead records can be searched and paged; lead conversion requires a user action. Add a service catalog entry, then choose its service or enter a custom line item in a proposal or draft invoice. Totals are calculated by the API in integer minor units. Only draft invoices can be edited; issue them explicitly, record payments only after confirming receipt, and use cancellation/reversal records to correct financial history. Finance shows payments received and expense entries separately by currency. It does not treat proposals or issued invoices as cash received. Test results appear only after a user records an execution. Deployment entries are metadata only and do not trigger deployments. Notification preparation creates deduplicated in-app reminders; email delivery is not configured by this workflow.

Existing generic workspace business records remain accessible through the legacy record endpoints. Review `GET /api/v1/business/legacy-migration/preview` or run the migration command in dry-run mode against an isolated database copy before any apply. Source records are retained. Legacy proposals/invoices and legacy income without verified payment history are left for manual review.
